结论：**这个库不是“标签堆”，而是“制作简报”**。高质量条目大量使用镜头、光线、材质、版式、精确文案和一致性约束。

## 二、七个来源的写法差异

| 来源 | 条数 | 中位长度 | 特征 |
| --- | --- | --- | --- |
| awesome-gpt-image | 43 | 64 | 中文一句话场景种子，偏生活写实，留白多，靠模型补全 |
| awesome-gpt4o-image-prompts | 75 | 240 | 英文短简报，产品/3D/UI 为主，商业化、干净 |
| banana-prompt-quicker | 278 | 141 | 中文短提示 + 参考图，模板感强，适合快速复刻 |
| davidwu-gpt-image2-prompts | 476 | 884 | 中英双语长提示，结构化，大量 `{argument}` 占位符 |
| freestylefly-gpt-image-2 | 438 | 1067 | 英文制作简报，产品/海报/信息图/分镜，细节最完整 |
| youmind-gpt-image-2 | 125 | 485 | 中文 JSON 版式规范，适合 UI/信息图/海报 |
| youmind-nano-banana-pro | 128 | 367 | 中文 JSON/参数模板，偏设计与商业视觉 |

三种典型原型：

1. **一句话种子**：`生成一张 TikTok 直播截图`。优点是快，缺点是全靠模型默认值，出图不稳定。
2. **制作简报**：一段到多段英文/中文，写清主体、镜头、光线、材质、风格、比例。适合摄影、产品、电影感场景。
3. **结构规范**：JSON 或分节标题，写清 layout、sections、count、position、copy。适合 UI、信息图、海报、VI、分镜。

**本 skill 的做法**：把第 1 种需求，按第 3 种的结构展开，再用第 2 种的语言密度写出来。

## 三、高质量提示词的 12 个共同点

1. **主体前置且具体**
   不写“一个美女”，写“28 岁左右的东亚女性，鹅蛋脸、杏仁眼、自然妆、黑发低盘发、穿米白针织衫”。

2. **镜头语言明确**
   景别 + 机位 + 焦距 + 光圈 + 景深。高频：35mm、50mm、85mm、f/2、shallow depth of field。

3. **光线有方向、有质感**
   不写“光线很好”，写“右上方柔和窗光，脸部有轮廓光，背景有暖色实用灯”。

4. **环境分三层**
   前景、中景、背景；再加天气、时间、空气感（雾/尘/雨/蒸汽）。

5. **材质与表面处理**
   matte / glossy / chrome / frosted glass / brushed metal / linen / ceramic / condensation。材质决定“贵不贵”。

6. **风格栈完整**
   媒介 + 流派/时代 + 技法 + 线条 + 上色 + 纹理 + 色板。例：“复古 1960s 旅行海报，丝网印质感，有限色板，纸张磨损”。

7. **版式可执行**
   网格、模块数、位置、留白、字号层级、对齐方式。设计类提示词几乎都靠这一层拉开差距。

8. **精确文案**
   把要出现的字用引号写死，指定语言、字体类别、位置、层级，并加“只出现这些文字，无乱码”。

9. **一致性协议**
   “同一角色/产品在所有格子中保持一致”，并重复关键身份特征。改造类则写“保留清单 / 改变清单”。

10. **多格/图层分段**
   先写共享设定，再逐格写 `Panel 1/2/3...`；或用“图层索引 + 片段”描述分层蒙太奇。

11. **参考图规则**
   “以附图为唯一参考”“图 1 管身份、图 2 管服装、图 3 管风格”；明确 preserve / change / do not。

12. **负面与边界**
   摄影类多写“no plastic skin / no extra fingers / no watermark”；UI 类多写“no gibberish / no duplicated widgets”；分镜类多写“no inconsistent character”。

## 四、结构选择：什么类型用什么写法

| 类型 | 推荐结构 | 原因 |
| --- | --- | --- |
| 摄影/写实 | 散文式，3–6 段 | 镜头、光线、材质需要连贯叙述 |
| 插画/3D | 散文 + 风格栈 | 媒介和技法需要组合，不宜过度碎片化 |
| 海报/信息图 | 分节或 JSON | 版式、模块、文案需要精确计数和位置 |
| UI/游戏界面 | 分节或 JSON | 组件、状态、文案、间距必须逐项写 |
| 品牌/VI | 分节或 JSON | 网格、应用清单、色板、字体需要清单化 |
| 多格/分镜 | 共享设定 + 逐格列表 | 先保证一致性，再保证叙事 |
| 参考图改造 | preserve / change / do not 三段 | 防止身份、构图、风格被一起改掉 |

## 五、语言策略

- **中文提示**适合：中文文案、版式、国风、信息图、UI 文案、品牌命名。
- **英文提示**适合：摄影镜头、光线、材质、艺术流派、3D 渲染、电影感。
- **混合**最实用：中文叙事 + 英文视觉术语，例：“35mm 镜头，f/2，浅景深，editorial street photography”。
- **不要整段中英双语重复**：如果两段都含文字指令，模型可能把两种语言都画进画面。需要双语时，明确“输出语言：中文，仅出现中文文案”。
- **精确文案优先用中文写死**，不要依赖模型翻译。

## 六、常见失败模式

1. **空泛形容词**：“高级、好看、有质感、氛围感”没有可执行信息。
2. **主体不明确**：画面里同时有 5 个重点，模型不知道看谁。
3. **文字太多**：一张图塞 10 段文案，必然乱码。
4. **风格冲突**：“超写实 + 卡通 + 3D + 水彩”同时出现。
5. **格数太多**：16 格以上，角色和细节很容易崩；4–9 格更稳。
6. **没有比例**：模型默认 1:1，海报/UI 被压扁。
7. **没有参考图规则**：说了“保持这个人”，却没写 preserve 清单。
8. **长而无结构**：2000 字一段，关键信息被淹没。
9. **负面词过长**：几十个 no，模型反而抓不住重点；负面词只保留 5–10 个关键项。
10. **照搬真实品牌/名人**：容易产生侵权、虚假代言或身份误导；默认改为虚构品牌/虚构人物。

## 七、标签体系的噪声

库里的 159 个标签存在明显问题：

- 同一概念中英重复：`UI` / `UI与界面` / `UI & Interfaces`。
- 标签与内容不符：`UI与界面` 下混入摄影、信息图、海报。
- 来源标签混入内容标签：`gpt-image-2`、`nano-banana-pro`、`moosl/...` 不是内容分类。
- 一个条目挂 6–8 个标签，无法直接当主类。

因此本 skill **不按标签路由**，而按“用户最终要的交付物”路由（见 `taxonomy.md`）。

## 八、本 skill 的取舍

- **12 个大类**：覆盖产品、品牌、海报、信息图、UI、摄影、插画、3D、角色、分镜、社交、改造。
- **18 个配方**：每个配方给出必填槽、结构骨架、默认值、负面。
- **1 套词库**：镜头、光线、材质、风格、版式、字体、负面、比例。
- **9 个示例**：从一句话到可粘贴提示词，覆盖最常见的商业与内容场景。
- **不收录**：擦边/未成年暗示、真实名人换脸、未授权品牌仿冒、纯堆砌“masterpiece, 8K”的无效模板。
